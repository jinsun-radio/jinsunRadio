# 三分鐘 Demo 影片｜設計與講稿

2026 AI 創新獎複審用。目標長度 **3:00**（180 秒），畫布 1920×1080。

本片要證明三件事，缺一不可：
1. **問題是真的**——不是想像出來的市場，是團隊自己家裡發生的事。
2. **硬體是我們做的**——不是買現成模組貼牌，機殼、電路、韌體都是自己組的。
3. **閉環是通的**——不是「偵測到就通知」，而是有人接單、有人到場、有人回報。

第 3 點是本片的主戲（85 秒），也是與市面上 SOS 按鈕／智慧音箱拉開差距的地方。

### 直式影片放進橫式畫布

兩支硬體素材是 720×1280。**不要拉伸、不要滿版裁切**（會切掉機身邊緣，也會切掉桌面的工具）。

```bash

"[0:v]scale=1920:-1,boxblur=40:5,crop=1920:1080[bg]; \
 [0:v]scale=-1:950[fg]; \
 [bg][fg]overlay=(W-w)/2+380:(H-h)/2" \
-c:a copy demo_landscape.mp4
```

三欄並排（收音機｜家屬｜志工）用 `hstack`，每欄先 `scale=-1:1000`：

```bash
ffmpeg -i radio.mp4 -i family.mp4 -i volunteer.mp4 -filter_complex \
"[0:v]scale=-1:1000[a];[1:v]scale=-1:1000[b];[2:v]scale=-1:1000[c]; \
 [a][b][c]hstack=inputs=3,pad=1920:1080:(ow-iw)/2:(oh-ih)/2" three_up.mp4
```

### 音訊

- **裝置的 TTS 一律用實錄原音**，不要事後配音。喇叭的音質、房間的殘響，都是真實性的一部分。
- 旁白與裝置語音**不要重疊**。裝置說話時旁白全靜。
- 背景音樂壓在 −22 dB 左右，裝置說話時再降 6 dB（side-chain 或手動包絡）。
- 建議 BGM：前半沉靜鋼琴，D3（1:30 三端亮起）換成有推進感的節奏，F 段收回鋼琴。

### 字幕

**全片上字幕，包含裝置語音**（用不同顏色或加上「🔊 收音機」前綴區分）。評審很可能靜音看，沒字幕等於白做。

## 五之一、三端網站的 demo 操作腳本

### 為什麼要「一次連續操作」而不是分鏡頭擺拍

觸發一次跌倒之後，後面全部是後端自己跑的級聯：20 秒升級 → 開派遣單 → 志工接單 →
`travel.js` 推著志工座標移動 → 跨過 250 公尺 → `progress.js` 下發接近預告 → 到場。
**沒有任何一步是可以「重來一次剛好那一格」的**，時間全由伺服器決定。

所以正確做法是：三個瀏覽器視窗同時開好、整個桌面錄一份，**跑一次完整 loop（約 100 秒）**，
另外各視窗再單獨錄一份，事後照粗剪的時間碼切。跑壞了就重置資料再跑一次，不要試圖分段補拍。

---

### 步驟 0：錄影前的環境準備

#### 0-A　Render 環境變數（已寫進 `render.yaml`，隨 push 生效）

預設 12 步×2 秒＝24 秒走完全程，對錄影太快：地圖上看不到移動，而且每步跨距太大，
座標會從 250m 外「跳」進 60m 內，接近預告會被「太近就不預告」的判斷**正確**擋掉
（2026-07-29 實跑證實過這件事）。所以拉長成 20 步×3 秒＝60 秒：

| 變數 | 值 | 位置 |
|---|---|---|
| `TRAVEL_STEPS` | `20` | `render.yaml`（已提交） |
| `TRAVEL_STEP_MS` | `3000` | `render.yaml`（已提交） |

**`APPROACH_METERS` 不用改，保持程式預設 250。** 配上 0-B 把志工起點設在 1460 公尺，
每步約 73 公尺，遞減到第 17 步剩約 219 公尺就會觸發接近預告（T+51s），
第 20 步到場（T+60s），兩者間隔約 9 秒，剪得開：

| 步 | 剩餘距離 | 事件 |
|---|---|---|
| 16 | 292 m | >250，不播 |
| **17** | **219 m** | ≤250 且 >60 → **接近預告** |
| 20 | 0 m | 到場 → 「到您家門口了，馬上進來看您」 |

> 起點距離變了就要重算。門檻 250 是正式值，不要為了 demo 去動它——
> 動它等於改掉產品行為，而 20 步×3 秒只是模擬器的播放速度。

#### 0-B　Supabase 資料歸零（SQL Editor）

2026-07-29 實跑一輪後確認線上有 **3 張跨長輩的殘留未結案單**，最嚴重的是陳玉蘭那張
「已等 **3923 分**（65 小時）・已廣播請支援」，看門狗還在持續廣播——志工端一開就被
全螢幕來單彈窗擋住，連捲動都不行。所以不能只清 elder-1，要全部清乾淨：

```sql
-- ① 清掉所有未結案的派遣單與其事件（task_messages 走 cascade 自動清）
delete from dispatch_tasks
 where status in ('pending', 'accepted', 'arrived');

delete from radio_events
 where status in ('open', 'escalated');

-- ② 長輩狀態全部回到「正常」（trigger 只會往上調，不會自己降回來）
update elders set severity = 'normal';

-- ③ 志工阿明歸位到距林阿春約 1.5 km 的起點並確保上線。
--    實跑時阿明在 10 km 外，ETA 算出 34 分鐘，跟腳本的「大約六分鐘」差太多；
--    1.5 km 配 TRAVEL_STEPS=20 → 每步約 73 m，才跨得過 500 m 門檻拍到接近預告。
update volunteers
   set lat = 25.0453, lng = 121.5565, online = true
 where name = '阿明';

-- ④ 其餘志工都上線（就近派單的候選池才夠真實）
update volunteers set online = true where name <> '俊傑';

-- ⑤ 長輩資料補齊：志工卡片出現「長輩（0 歲）」就是這裡沒對上
update elders
   set name = '林阿春', age = 82, lat = 25.0358, lng = 121.5665,
       device_serial = 'JS-0001',
       preferred_lang = 'taigi',
       address = '110臺北市信義區安康里松仁路123號'
 where id = 'elder-1';
```

**開拍前用這段驗證歸零成功**（三個數字都要是 0）：

```sql
select
  (select count(*) from dispatch_tasks
    where status in ('pending','accepted','arrived'))            as 未結案派遣單,
  (select count(*) from radio_events
    where status in ('open','escalated'))                        as 未結案事件,
  (select count(*) from elders where severity <> 'normal')       as 非正常長輩;
```

再確認阿明的起點距離（應該是 1400～1500 公尺）：

```sql
select round(
  6371000 * 2 * asin(sqrt(
    power(sin(radians(e.lat - v.lat) / 2), 2) +
    cos(radians(v.lat)) * cos(radians(e.lat)) *
    power(sin(radians(e.lng - v.lng) / 2), 2)
  ))
) as 阿明距林阿春公尺
from volunteers v, elders e
where v.name = '阿明' and e.id = 'elder-1';
```

> **每跑一次 loop 就要重跑 ①～③**，否則第二次會接到上一輪的舊單。
